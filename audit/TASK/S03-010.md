# Task ID: S03-010

**Title:** DiscoverService Di-instantiasi Ulang di Setiap Request
**Priority:** P2
**Sprint:** sprint-03-performance
**Status:** TODO

## Source Audit
[PERF-P16, SVC-01]

## Root Cause
Objek servis penyedia lagu campuran difabrikasi ulang berulang menjadi var/objek python memori baru (diinstansiasi gres) terus menerus per panggilan hit websocket, yang menambah cycle beban CPU ringan dan mem-bypass teknik efisiensi cache memori singel. Module fungsional DiscoverService yang seharusnya cuma sebagai service stateless instansi Singleton, justru di-build berulang setiap kali masuknya request. Ini membuang waktu eksekusi VM internal (meski relatif kecil).

## Location
`server/handlers/ws/discover_handlers.py:17-33`

## Current Behavior
Pembentukan muatan data discover memanggil database dengan batas statis (`DISCOVER_RECENT_LIMIT`, dll) namun sama sekali tidak menyediakan kontrol parameter asupan seperti `offset` maupun `page`, sehingga mustahil melakukan infinite-scroll bagi antarmuka klien.

## Expected Fix
Lakukan refactor/perbaikan pada lokasi kode terkait agar sesuai dengan arsitektur yang aman dan benar. Implementasikan mekanisme garbage collection atau batas ukuran (max limit) serta timeout/pruning untuk mencegah kebocoran memori (memory leak).

## Constraints
- Tidak boleh merusak kapabilitas streaming inti dari player MPV.
- Modifikasi arsitektur tidak boleh mengorbankan performa saat melayani banyak websocket connection.
- Ikuti standard code quality dan format di `Task_execution_rules.md`.
