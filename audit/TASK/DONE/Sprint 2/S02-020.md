# Task ID: S02-020

**Title:** CacheResolver._fetching bisa menunda waiter selamanya (Memory Leak)
**Priority:** P1
**Sprint:** sprint-02-stability
**Status:** DONE

## Source Audit
[BUG-B15, DB-017, EXC-01, EXC-02, RTY-01, CAC-03]

## Root Cause
Event listener yang menahan task async untuk antrean stream resolving tak mengeset parameter batasan waktu (timeout) apapun, mengakibatkan thread melayang mati (hang deadlock loading spinner di frontend) apabila task yang ditunggu kebetulan tertutup tiba-tiba (crash) sebelum melaporkan sinyal kelar. Jika ytdlp melemparkan exception ketika fetching, Waiter B akan diputus, lalu mengeksekusi fetch ulang seakan tidak pernah ada attempt, yang dapat menyebabkan concurrent parallel call berlebih secara...

## Location
`cache/resolver.py:42-44`

## Current Behavior
Siklus loop rekursi tanpa batas jika task fetch yt-dlp melempar exception: waiter dibangunkan lalu memanggil get `resolve()` lagi, yang men-trigger gagal tak terbatas (Thundering herd/Memory Leak).

## Expected Fix
Lakukan refactor/perbaikan pada lokasi kode terkait agar sesuai dengan arsitektur yang aman dan benar. Gunakan mekanisme penguncian (contoh: asyncio.Lock) untuk mencegah race condition. Bungkus akses variabel mutasi dalam blok `async with lock:`.

## Constraints
- Tidak boleh merusak kapabilitas streaming inti dari player MPV.
- Modifikasi arsitektur tidak boleh mengorbankan performa saat melayani banyak websocket connection.
- Ikuti standard code quality dan format di `Task_execution_rules.md`.

## Completion Report
- **Task ID**: S02-020
- **Objective**: Mengatasi malfungsi siklus tak terhingga (infinite loop retry) dan kondisi balapan (race condition) pada mekanisme cache resolving ketika banyak klien meminta track yang sama di kala pemanggilan yt-dlp melambat atau gagal.
- **Summary**: Refaktor pada `CacheResolver._fetching` dari pendekatan usang `asyncio.Event` (yang tak menyalurkan pengecualian secara propagatif) diubah menjadi `asyncio.Future` dengan kawalan ketat `asyncio.Lock` dan `asyncio.wait_for` (timeout 30 detik untuk *fetcher*, 35 detik untuk *waiters*). Jika terjadi *error fetch*, pengecualian dioper dengan aman kepada seluruh penunggu (*waiters*), dan entri dibersihkan, sehingga mencegah _thundering herd retries_.
