## Root Cause
Di beberapa versi aiosqlite, argumen list secara kaku tidak diterima pada query IN dengan array tunggal (['abc'] diinterpretasikan sebagai char sekuensial ('a','b','c')), dan list tersebut seharusnya dikoversi terlebih dahulu ke tuple sebelum eksekusi SQL.

## Location
`cache/repositories/track_repository.py:136-137`

## Current Behavior
Kumpulan identifier langsung dioper bertipe data iteratif array `list` ketimbang diserialisasi sebagai `tuple` parameter bind SQLite murni.

## Expected Fix
Lakukan refactor/perbaikan pada lokasi kode terkait agar sesuai dengan arsitektur yang aman dan benar. Gunakan parameterisasi SQL yang benar (parameter binding/tuple) alih-alih manipulasi string mentah untuk query database.

## Constraints
- Tidak boleh merusak kapabilitas streaming inti dari player MPV.
- Modifikasi arsitektur tidak boleh mengorbankan performa saat melayani banyak websocket connection.
- Ikuti standard code quality dan format di `Task_execution_rules.md`.
