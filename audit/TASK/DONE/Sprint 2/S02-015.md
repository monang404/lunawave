**Priority:** P2

## Source Audit
[BUG-B10, SVC-03]

## Root Cause
Layanan objek class in-memori status volume mengambil nilainya sendiri saja saat boot tanpa mengorelasikan sinkronisasinya ke player daemon mpv asli, sehingga slider volume tidak terpantul-balas (out of sync) nilai benarnya bila mpv diboot berbekal state lawas. Penggunaan variabel snapshot (self.current_volume) dapat berbeda dengan state yang sesungguhnya apabila state dimutasi secara eksternal. Dua call serentak (race condition) juga dapat membaca dan menambahkan volume yang salah karena duplik...

## Location
`engine/volume_service.py:19`

## Current Behavior
Servis volume hanya memegang cerminan status awal memori volume saat inisialisasi tanpa secara asinkron memantau status get_volume mutakhir pada layer daemon OS Mpv.

## Expected Fix
Lakukan refactor/perbaikan pada lokasi kode terkait agar sesuai dengan arsitektur yang aman dan benar. Gunakan mekanisme penguncian (contoh: asyncio.Lock) untuk mencegah race condition. Bungkus akses variabel mutasi dalam blok `async with lock:`.

## Constraints
- Tidak boleh merusak kapabilitas streaming inti dari player MPV.
- Modifikasi arsitektur tidak boleh mengorbankan performa saat melayani banyak websocket connection.
- Ikuti standard code quality dan format di `Task_execution_rules.md`.
